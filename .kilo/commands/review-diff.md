# Review diff

Проведи код-ревью указанной цели перед мержем.

Параметр команды — текст, переданный после `/review-diff`. Это может быть путь к файлу или имя ветки.

1. Если параметр не передан — не выбирай цель самостоятельно: задай пользователю вопрос, какой файл или ветку проверить, и не начинай ревью до ответа.
2. Если параметр — путь к файлу, проверь изменения этого файла относительно `main`.
3. Если параметр — имя ветки, проверь изменения этой ветки относительно `main`.
4. Если параметр не является ни существующим файлом, ни веткой — запроси уточнение, не угадывай.
5. Используй правила из `.kilo/skills/code-review/SKILL.md`.
6. Оформи результат в формате skill: `Blocker`, `Comment`, затем итог с решением, можно ли мержить.
7. Добавь результат в `docs/setup/commands.md`, указав точный вызов команды. Не удаляй результаты предыдущих запусков.

Не переписывай правила code review внутри команды — источником остаётся `.kilo/skills/code-review/SKILL.md`.

Чего не делать: не исправляй найденные проблемы сам, не делай рефакторинг и не выходи за переданную цель ревью.
