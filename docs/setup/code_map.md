# Карта кода для правила пробега

## Как считается решение

Решение approve / review / reject рассчитывается в доменной логике.

`DecisionEngine::decide()` сейчас принимает только LTV и определяет решение по порогам из `rules.php`.

Текущая логика:

- если `$ltv < approveMax` → `approve`;
- если `$ltv <= reviewMax` → `review`;
- иначе → `reject`.

В `AssessmentService::assess()` расчёт решения вызывается через:

```php
$decision = $this->decisionEngine->decide($ltv);
```

## Что сейчас происходит с пробегом

Пробег приходит в данных заявки.

`ApplicationValidator::validate()` проверяет допустимый диапазон пробега:

`0 <= mileage <= 500000`.

Если значение выходит за диапазон, возникает `ValidationException`, и решение по заявке не рассчитывается.

На `approve / review / reject` пробег сейчас не влияет.

Порог `400000` в текущей логике решения отсутствует.

## Новое правило

Необходимо добавить правило:

- `mileage <= 400000` — текущее принятие решения продолжается;
- `mileage > 400000` — решение `review`.

Сейчас `DecisionEngine::decide()` принимает только `float $ltv`, поэтому пробег туда напрямую не передаётся.

Для реализации правила потребуется передать пробег в расчёт решения либо выполнить проверку до вызова `DecisionEngine::decide()`.

## Точка вставки

Файл: `backend/src/Domain/DecisionEngine.php`  
Функция: `DecisionEngine::decide()`.

Текущий код вокруг точки вставки:

```php
public function decide(float $ltv): string
{
    if ($ltv < $this->approveMax) {
        return self::APPROVE;
    }
}
```

Правило по пробегу должно проверяться до принятия решения по LTV, чтобы значение `mileage > 400000` приводило к `review` до возможного возврата `approve`.

Для этого в расчёте решения потребуется доступ к значению пробега.
