# 2.2.2 — Проверка автоматического выбора skill

Запрос в обоих случаях был одинаковым:

`Посмотри backend/src/Repository/ApplicationRepository.php перед мержем.`

Слово «скилл» в запросе не использовалось.

| Со skill `code-review` | Без skill |
|---|---|
| Агент самостоятельно определил, что запрос подходит под `code-review`, и загрузил `.kilo/skills/code-review/SKILL.md`. | Агент выполнил обычное код-ревью без `code-review`. |
| Замечания были разделены на `Blocker` и `Comment`. | Замечания были оформлены обычным нумерованным списком. |
| Для каждого замечания использовался формат: что не так → почему это важно → что нужно исправить. | Единого формата для каждого замечания не было. |
| В конце был явный итог: `Блокирующие проблемы: да` и `Можно мержить: нет`. | Итог был менее формальным: `До мержа желательно закрыть хотя бы 1 и 2`. |

## Ответ со skill

Агент выделил два blocker:

1. Отсутствие транзакции в `ApplicationRepository::save()`.
2. SQL-инъекция через `$status` в `listApplications()`.

Дополнительно как `Comment` указал N+1 запросы, отсутствие проверки формы входных массивов, ограничение `applicant_ref` и отсутствие тестов.

Итог агента:

- Блокирующие проблемы: да.
- Можно мержить: нет.

## Ответ без skill

Агент выделил:

1. SQL injection в `listApplications`.
2. Отсутствие транзакции в `save()`.
3. N+1 запросы в `listApplications`.
4. Проверку поведения PDO / `ERRMODE_EXCEPTION`.

Итог агента:

`До мержа желательно закрыть хотя бы 1 и 2 — это и безопасность, и целостность данных.`

## Вывод

Со skill агент сделал ревью в нашем командном формате: разделил замечания на `Blocker` и `Comment`, для каждого указал проблему, риск и исправление и дал однозначное решение о возможности мержа. Без skill замечания были обычным списком и такого формата и явного решения `можно мержить / нельзя` не было.

- `Объясни, как работает ApplicationRepository.php` → `code-review` не взялся, агент просто объяснил код через ast-index.

Итоговый description:

Вывод: description достаточно точно определяет границу применения — skill включается на запрос о готовности изменений к мержу и не включается на обычное объяснение кода.
