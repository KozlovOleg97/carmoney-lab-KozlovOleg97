# E2E проверка двух сценариев через Playwright

Сервис: http://localhost:8080/
Дата: 2026-10-06

## Сценарий 1 — пробег 400001, ожидаемое решение `review`

### Введённые значения
- Идентификатор клиента: `CL-0025`
- VIN: `XTA21099998765432`
- Год выпуска: `2019`
- Пробег, км: `400001`
- Оценочная стоимость, ₽: `900000`
- Запрошенная сумма, ₽: `450000`
- Срок, месяцев: `24`

### Действия пользователя (дословно по снимкам)
1. `playwright_browser_navigate` → `http://localhost:8080`.
   Page URL: `http://localhost:8080/`
   Page Title: `Предварительная оценка заявки — carmoney-lab`
2. `playwright_browser_snapshot` — форма отображается со значениями по умолчанию (`Пробег, км: 84000` и т. д.), кнопки `Отправить заявку` и `Только рассчитать LTV`.
3. `playwright_browser_fill_form` → поле «Пробег, км» = `400001`.
   Снимок после ввода подтвердил значение поля: `Пробег, км: 400001`.
4. `playwright_browser_click` → кнопка `Отправить заявку`.
5. `playwright_browser_snapshot` — на странице появился блок результата.
6. `playwright_browser_take_screenshot` → `docs/setup/mileage-400001-review.png`.

### Что показала система (дословно из `playwright_browser_snapshot`)
Блок под формой:
- Заголовок: `Решение`
- `Решение`: `review`
- `LTV`: `50 %`
- `Возраст авто`: `7 лет`
- `Одобренный лимит`: `0 ₽`
- `Номер заявки`: `26`

## Поиск второго места в UI, где видно правило пробега

Что было проверено через Playwright MCP (только действия в браузере, без чтения кода/HTML через shell/read):

1. `playwright_browser_hover` на поле «Пробег, км» — `playwright_browser_snapshot` после наведения не изменился: новых подсказок, тултипов или текстов рядом с полем не появилось.
2. `playwright_browser_click` на поле «Пробег, км» + `playwright_browser_press_key Tab` — фокус ушёл на следующее поле «Оценочная стоимость, ₽», никакого inline-сообщения о диапазоне пробега рядом с полем не появилось.
3. `playwright_browser_fill_form` «Пробег, км» = `100000000` (значение выше лимита) — `playwright_browser_snapshot` показал только изменившееся значение поля, без какого-либо inline-предупреждения.
4. `playwright_browser_click` «Только рассчитать LTV» при `Пробег, км: 600000` — `playwright_browser_snapshot` показал тот же блок под формой:
   - Заголовок: `Заявка не принята`
   - Элемент списка: `mileage: Пробег от 0 до 500000 км`
   Это тот же самый блок «результат/ошибка», который уже зафиксирован в сценариях 1 и 2, отдельного места в UI не появилось.
5. `playwright_browser_click` «Только рассчитать LTV» при `Пробег, км: 100000` — блок под формой показал:
   - Заголовок: `Решение`
   - `Решение`: `approve`
   - `LTV`: `50 %`
   - `Возраст авто`: `7 лет`
   - `Одобренный лимит`: `450 000 ₽`
   - `Номер заявки`: `не сохранена`
   Тоже тот же блок «результат/ошибка».
6. `playwright_browser_find` по подстрокам `Пробег`, `км`, `500000`, `mileage`, регулярному выражению `/(от 0|500000|диапазон|ограничен)/` — нашлись только:
   - метка поля `Пробег, км` и само поле `Пробег, км: 100000` в форме,
   - элемент списка `mileage: Пробег от 0 до 500000 км` в блоке под формой (тот же, что в сценарии 2).
   Других мест с упоминанием правила пробега в DOM не найдено.

### Вывод

Второго места в пользовательском интерфейсе, кроме уже проверенного блока результата/ошибки под формой, где пользователю видно влияние или ограничение правила пробега, фактически нет. Никаких подсказок рядом с полем «Пробег, км», тултипов, inline-валидации, отдельных индикаторов или других блоков, связанных с правилом пробега, через действия в браузере не обнаружено. Скриншот для этого случая не сделан — снимать нечего.
