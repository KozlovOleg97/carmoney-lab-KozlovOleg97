# Spec MILEAGE: правило пробега в решении по заявке

Источник требований: `docs/intent/intent_MILEAGE.md` (все Open questions закрыты,
подробности — `grill_MILEAGE.md`).

## Входит / не входит

Входит:

- Учёт пробега автомобиля при расчёте решения по заявке (approve / review / reject):
  пробег больше 400 000 км понижает approve до review. — intent, раздел «Замысел».

Не входит:

- Валидация входа заявки: диапазон пробега 0..500 000 км, поведение при
  отсутствии поля, null, пустой строке и явном нуле. — intent, раздел «Не входит».
- Пересчёт уже сохранённых решений по новому правилу. — intent, раздел «Не входит».
- Задача LOAN-12: расчёт лимита по возрасту автомобиля. — intent, раздел «Не входит».
- Всё, кроме расчёта решения: хранение заявок, структура и тестовые данные БД,
  HTTP-слой, фронтенд, моки. — intent, раздел «Не входит».

## Требования и критерии приёмки

Числа и их источники:

- 400 000 км — граница правила пробега. Источник: intent, Constraint 1
  (ответ в интервью; формулировка задачи «не больше 400 000 км, иначе review»).
- 60% и 85% — пороги LTV: LTV < 60% → approve; 60% <= LTV <= 85% → review;
  LTV > 85% → reject. Источник: код `backend/src/Domain/DecisionEngine.php`,
  числа — `backend/config/rules.php` (`ltv.approve_max` = 60.0, `ltv.review_max` = 85.0);
  неизменность подтверждена ответом в интервью (intent, Constraint 3).
- 0..500 000 км — диапазон валидации пробега; значения 400 001..500 000 —
  валидный вход. Источник: `backend/config/rules.php`
  (`vehicle.max_mileage_km` = 500000); ответ в интервью (intent, Constraint 4).
- 0 — `approved_limit` у всех не-approve решений, включая review из-за пробега.
  Источник: код `backend/src/Domain/AssessmentService.php`; ответ в интервью
  (intent, Constraint 7).

### REQ-MILEAGE-01

Если пробег автомобиля не больше 400 000 км, решение по заявке считается
по текущей логике LTV без изменений. — intent, раздел «Замысел»; Constraint 1.

- AC-MILEAGE-01 (REQ-MILEAGE-01): Given заявка с LTV < 60% (approve по LTV)
  и пробегом 399 999 км; When рассчитывается решение; Then approve.
- AC-MILEAGE-02 (REQ-MILEAGE-01): Given заявка с пробегом ровно 400 000 км
  (граница включительная); When рассчитывается решение; Then решение то же,
  что по LTV без правила пробега (например, при LTV < 60% — approve).
- AC-MILEAGE-03 (REQ-MILEAGE-01): Given заявка с LTV в 60% <= LTV <= 85%
  и пробегом 399 999 км; When рассчитывается решение; Then review (как по LTV).

### REQ-MILEAGE-02

Если пробег автомобиля больше 400 000 км, заявка, которая по LTV получила бы
approve, понижается до review. — intent, раздел «Замысел»; Constraint 1.

- AC-MILEAGE-04 (REQ-MILEAGE-02): Given заявка с LTV < 60% и пробегом
  400 001 км (первое значение, на котором правило срабатывает);
  When рассчитывается решение; Then review, не approve.
- AC-MILEAGE-05 (REQ-MILEAGE-02): Given заявка с LTV < 60% и пробегом
  500 000 км (верхняя граница валидного входа); When рассчитывается решение;
  Then review.

### REQ-MILEAGE-03

При пробеге больше 400 000 км правило понижает только approve до review:
review-зона LTV остаётся review, reject не смягчается — при LTV > 85% итог
reject независимо от пробега. — intent, Constraint 2 (ответ в интервью, вопрос 1).

- AC-MILEAGE-06 (REQ-MILEAGE-03): Given заявка с 60% <= LTV <= 85% и пробегом
  400 001 км; When рассчитывается решение; Then review (не reject).
- AC-MILEAGE-07 (REQ-MILEAGE-03): Given заявка с LTV > 85% и пробегом
  400 001 км; When рассчитывается решение; Then reject.

### REQ-MILEAGE-04

Существующая логика решения по LTV не меняется: LTV < 60% → approve;
60% <= LTV <= 85% → review; LTV > 85% → reject. — intent, Constraint 3
(код `backend/src/Domain/DecisionEngine.php`, числа — `backend/config/rules.php`;
ответ в интервью, вопросы 1, 5).

- AC-MILEAGE-08 (REQ-MILEAGE-04): Given заявка с пробегом, на который правило
  не срабатывает (например, 399 999 км); When LTV < 60%; Then approve;
  When 60% <= LTV <= 85%; Then review; When LTV > 85%; Then reject.

### REQ-MILEAGE-05

`approved_limit` при review из-за пробега равен 0, как у всех не-approve
решений. — intent, Constraint 7 (код `backend/src/Domain/AssessmentService.php`;
ответ в интервью, вопрос 3).

- AC-MILEAGE-09 (REQ-MILEAGE-05): Given заявка с LTV < 60% и пробегом
  400 001 км (approve по LTV понижен до review); When рассчитывается решение;
  Then decision = review и approved_limit = 0.

### REQ-MILEAGE-06

Правило действует только на расчёт решений по новым заявкам; уже сохранённые
решения не пересчитываются. — intent, Constraint 8 (ответ в интервью, вопрос 4).

- AC-MILEAGE-10 (REQ-MILEAGE-06): Given заявка, решение по которой сохранено
  до введения правила, с пробегом больше 400 000 км и approve по LTV;
  When правило введено; Then сохранённое решение остаётся approve (без пересчёта).

### Поведение при пустом или неизвестном пробеге

Диапазон валидации 0..500 000 км не меняется; значения 400 001..500 000 —
валидный вход. — intent, Constraint 4 (`backend/config/rules.php`;
ответ в интервью, вопрос 5).

- AC-MILEAGE-11 (REQ-MILEAGE-02, вход вне правила): Given заявка с пробегом
  0 км; When рассчитывается решение; Then решение по LTV без влияния правила
  пробега (явный 0 км — валидный вход).

Пробег не указан (поле отсутствует или null) — заявка отклоняется ошибкой
валидации, решение не рассчитывается. — intent, Constraint 5 (код
`backend/src/Domain/ApplicationValidator.php`). Валидация входа — вне рамок
задачи (intent, раздел «Не входит»), поэтому это AC фиксирует существующее
поведение, а не новое требование:

- AC-MILEAGE-12 (существующее поведение, вне рамок): Given заявка, где поле
  пробега отсутствует или равно null; When рассчитывается решение;
  Then заявка отклоняется ошибкой валидации, решение не рассчитывается.

Пустая строка пробега приводится к 0 км и валидна; известная дыра,
сознательно не закрывается. — intent, Constraint 6 (код
`backend/src/Domain/ApplicationValidator.php`; ответ в интервью, вопрос 2).

- AC-MILEAGE-13 (существующее поведение, вне рамок): Given заявка, где поле
  пробега — пустая строка; When рассчитывается решение; Then пробег трактуется
  как 0 км и решение считается по LTV (дыра `'' → 0` остаётся).

## Open questions из intent

Открытых вопросов нет. Все вопросы интервью закрыты заказчиком
(`grill_MILEAGE.md`, intent, раздел «Open questions»):

- «review или reject при пробеге > 400 000 км и одновременно плохом LTV» —
  закрыт: ответом заказчика (вопрос 1): reject, правило понижает только approve
  ( REQ-MILEAGE-03, AC-MILEAGE-06, AC-MILEAGE-07).
- «пустая строка / 0 км как "пробег не указан"» — закрыт: ответом заказчика
  (вопрос 2): валидация не меняется, дыра `'' → 0` остаётся вне рамок
  ( AC-MILEAGE-12, AC-MILEAGE-13, раздел «Не входит»).
- «`approved_limit` при review из-за пробега» — закрыт: ответом заказчика
  (вопрос 3): 0, как у всех не-approve решений ( REQ-MILEAGE-05, AC-MILEAGE-09).
- «пересчёт сохранённых решений» — закрыт: ответом заказчика (вопрос 4):
  правило только на новые заявки, пересчёт не нужен ( REQ-MILEAGE-06,
  AC-MILEAGE-10, раздел «Не входит»).
- «радиус задачи» — закрыт: ответом заказчика (вопрос 5): только расчёт решения
  ( раздел «Входит / не входит»).

Перенесённых вопросов нет.
