## 2.1.1 — ast-index

При использовании ast-index агент действительно выполнял структурный поиск по коду.

Использованные команды:

- `ast-index search mileage 2>&1; ast-index search max_mileage_km 2>&1`
- `ast-index search mileage --limit 31 2>&1`

По сравнению с обычным поиском количество токенов снизилось с 94 490 до 67 867, число вызовов модели — с 6 до 4, стоимость — с $0.01598024 до $0.00508449.

Для запуска ast-index агент использовал CLI через bash. Встроенный Ask mode блокировал произвольный CLI, поэтому рабочий замер выполнялся в Code mode.

## 2.1.2 — Caveman

Для замера ast-index + Caveman агент использовал ast-index, в том числе:

- `ast-index --help`
- `ast-index usages mileage`
- `ast-index usages max_mileage_km`
- `ast-index search mileage`
- `ast-index search max_mileage`
- `ast-index search mileage -t text`
- `ast-index search mileage -t text --limit 31`

Caveman сделал итоговый ответ более коротким и плотным. Основные найденные места сохранились: доменная логика, конфигурация, тесты, БД и frontend. Часть поясняющего контекста и подробных описаний была сокращена.

На этом вопросе Caveman не дал экономии всей агентской сессии: ast-index + Caveman потребовал 241 142 токена против 67 867 у чистого ast-index.

## ⭐ Caveman без ast-index

Для отдельного замера ast-index был отключён. Агент подтвердил, что использовал обычный поиск через bash/Select-String и чтение файлов.

Caveman без ast-index потребовал:

- Input tokens: 214 675
- Output tokens: 3 767
- Всего токенов: 218 442
- Стоимость: $0.02912213
- Вызовов модели: 7

На данном вопросе больше пользы дал ast-index: чистый ast-index оказался самым дешёвым вариантом, потребовал меньше всего токенов и меньше обращений к модели.

## Вывод

Для задачи поиска использований по репозиторию структурный индекс ast-index оказался полезнее Caveman.

Caveman сокращает форму финального ответа, но сам по себе не гарантирует снижение стоимости всей сессии: дополнительные поиски и обращения агента могут перекрыть экономию на длине ответа.
